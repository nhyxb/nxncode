# 任务规划

先读取当前项目已有规则、文档和相关实现，区分用户目标、现有约束与需要核实的假设。沿用项目自己的文档和执行方式，不为一次小修改搭建新的管理体系。

明确用户最终能观察到的结果和验收条件。对于不可逆操作、外部发布或缺失的关键输入，标出真正需要用户决策的位置；能从项目推断的普通实现选择自行处理。

比较会影响实现的技术方案，给出选择及原因。任务按依赖拆分，每项说明改动范围、完成条件和最有价值的验证；优先验证可能推翻方案的风险。不要把阅读、思考或每个函数分别列成任务。

用户只要方案时交付可评审的计划；用户已要求实施时，记录必要计划后继续执行。保留已有未提交工作，完成一项就更新对应进度，结果与实际文件和验证证据一致。
