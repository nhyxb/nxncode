# 排查故障

先确认触发条件、预期行为、实际结果以及最后一次正常状态。使用现有日志、调用入口和相邻实现形成可复现的最小案例，避免一开始同时改动多个可疑位置。

把观察到的事实与猜测分开。优先用一个有区分度的检查验证最可能原因；日志只采集必要字段，隐藏密钥、Cookie 和用户私有内容。对超时、权限、缓存、过期异步结果和环境差异，沿实际数据流核对，不能靠重试成功证明根因。

修复产生错误的状态或契约，保留原有交互与兼容性。避免吞掉异常、放宽权限、全局重置数据或增加延时来掩盖问题。若同一操作重复得到相同错误，依据新证据调整方法。

先验证原始失败场景，再验证一个关键边界或相关回归；能有效防止复发时加入针对性测试。说明根因、实际修改、验证结果及仍未解决的限制。
