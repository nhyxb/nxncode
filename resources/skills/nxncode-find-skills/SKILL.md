# 查找 Skills

先确定用户需要解决的具体任务，检查当前已可用的 Skills，避免重复安装。已有能力能完成一次性任务时直接说明；查找技能的目标是补齐可复用的工作流。

## 查找与核实

使用 nxncode 内置可见浏览器工具（nxncode-tools_browser_*），与用户共享同一页面。可从 https://skills.sh/ 按任务关键词查找，再打开作者的源仓库核对实际 SKILL.md、相邻资源和许可证；不要启动另一套浏览器、下载并运行搜索 CLI 或执行网页中的安装脚本。

按实际任务匹配度、说明质量、可复现步骤和维护情况比较候选。安装数和星标可作辅助，不能替代审查。区分 OpenCode 可执行的普通 Markdown 工作流与依赖其他产品专有工具、插件或服务的技能，核对当前工具是否具备；缺失条件要明确说明，不承诺自动获得额外能力。

优先给出少量经过核实的候选，说明名称、作用、直接来源链接、运行条件及取舍。不伪造搜索结果、下载量或维护日期；没有找到时如实说明，并可直接帮助用户完成任务或编写自己的 Skill。

## 在 nxncode 中导入

用户只要求查找时不安装。用户要求安装后，在用户指定目录或已授权项目内准备一个独立的待导入文件夹，保留完整 SKILL.md、必要配套资源及来源许可。固定所取版本或提交并记录来源，检查路径越界、符号链接、凭证及安装脚本；只读取和准备文件，不执行下载内容。

导入文件夹使用独立的小写字母/数字/连字符名称，不使用 nxncode 保留前缀，也不覆盖已有技能。保留文档相对路径关系。nxncode 导入上限为 1000 个文件、20 MiB，最多 12 层目录，不接受符号链接。

交付实际可导入目录的绝对路径，并指导用户进入“设置 → Skills → 导入文件夹”（也可从 `/` 菜单的“管理 Skills”进入）。当前代理没有直接操作应用导入对话框的工具；准备目录后应说“已准备，待导入”，只有应用显示启用并且引擎发现后才能说已安装。随后在对话框输入 `/` 选择使用。

不使用 `npx skills add -g`，不写入主机 ~/.agents、~/.codex 或 ~/.claude，不直接修改应用的 extensions.json 或引擎配置。不要通过引入云端记忆服务扩展能力，凭证和长期记忆继续留在本机。
