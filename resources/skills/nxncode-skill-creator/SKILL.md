# 创建 Skills

根据用户的真实任务明确技能应处理什么、何时触发、完成结果及现有工具条件。用户已给出充分信息时直接编写；关键输入会改变技能范围时再集中询问。修改已有技能先检查相关资源和使用方式，保留仍有效的约束。

将可复用判断、非显然步骤和真正易错的约束写入说明，省去一般模型已经具备的常识。用户和项目规则优先，技能不扩大授权范围，不自行发布、发送消息、安装系统依赖或接入云端记忆。

## 可导入结构

在用户指定目录或已授权项目下生成独立文件夹，名称为小写字母开头、仅含小写字母/数字/连字符、最长 64 字符；不使用 nxncode 保留前缀。文件夹名作为导入 ID，避免与已有项冲突。

必需文件为大小写准确的 `SKILL.md`。示例：

```markdown
---
name: task-workflow
description: 清楚说明所完成的任务以及何时使用，避免吸引无关请求。
---

# 工作流

写出会改变执行决策的上下文、方法和完成标准。
```

name 与文件夹名一致，description 为简短的有效 YAML 字符串，含冒号等特殊字符时正确引用。正文说明目标、重要约束、适用工具、失败处理及可观察的交付结果；不要为了固定模板添加多余步骤。

较长的条件说明按需放入 references/，并在入口解释何时读取；只有确定性处理或重复执行有收益时才增加 scripts/；实际交付要复用的素材放 assets/。不创建空目录、占位文件或无用途的 agents/openai.yaml。资源使用目录内相对路径，不引用创建机器的私有绝对路径。

## 验证与交付

检查 YAML、name/description、正文和资源路径完整，无未完成占位。针对真实输入试跑有执行意义的辅助脚本，检查真实输出与一个关键失败边界；不要仅匹配标题或重复实现的文字。说明中提到的工具必须在 nxncode 实际可用；网页操作使用内置可见浏览器，不能假设有 Codex 专有 API。

文件夹不能包含符号链接，最多 1000 个文件、20 MiB、12 层目录。排除 .git、node_modules、.env、密钥和个人运行数据；保留复用资源的许可。技能不写主机共享 Skills 目录或应用私有配置。

交付真实文件夹的绝对路径、用途和验证结果。使用“设置 → Skills → 导入文件夹”把它加入 nxncode；若只是生成目录，明确仍待用户完成导入。内置技能由安装包维护，需要改编时创建新 ID 的副本导入；不要编辑包内文件或绕过应用的启停管理。导入并确认可用后通过 `/` 选择。
