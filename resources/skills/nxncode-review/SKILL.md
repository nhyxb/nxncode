# 代码审查

确认审查范围和比较基准，读取改动涉及的调用方、数据结构及必要测试。对于未提交工作，不把他人的修改重置或自动提交。未指定基准时先从当前改动和项目约定推断，无法确定时明确说明范围。

优先检查会改变行为的输入边界、异常恢复、异步竞争、资源清理、持久化兼容和访问授权。每个发现都要能指出具体触发条件及实际影响；不要把理论风险、已有问题或个人风格作为本次新缺陷。

给出精确文件位置、影响优先级、触发方式和建议修复方向。同一个根因合并说明；没有充分证据的猜测标为待核实。验证命令只围绕有争议的行为，不运行会修改外部系统的操作。

若没有发现明确问题，直接说明审查范围及验证限制。用户只要求审查时不擅自改代码；用户同时要求修复时，处理已确认问题并复验。
